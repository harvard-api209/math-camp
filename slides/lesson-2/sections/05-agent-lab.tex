\section{From Lesson 2 to Lab 2}
\subsection{Bounded help}

\begin{frame}{Goal for the live demonstration}
  The health table is built and the current verifier is green. Before using the
  table in a policy briefing, we want to strengthen \alert{one documented check}:

  \vspace{0.6em}
  \begin{block}{Our task}
    Confirm that \texttt{under5\_mortality} refers to World Bank indicator
    \texttt{SH.DYN.MORT} and is measured per 1,000 live births---without
    changing the table, sample, or transformation.
  \end{block}

  \vfill
  By the end, we should be able to explain why we used a builder, what we asked
  the agent to review, and what the independent verifier established.
\end{frame}

\begin{frame}[fragile]{Step 1: establish the baseline ourselves}
  First rebuild the table and run the existing checks:

\begin{lstlisting}
Rscript code/02-build-analysis.R
Rscript code/02-verify-analysis.R
\end{lstlisting}

  \begin{description}
    \item[Builder] Creates the saved table and its build record from the frozen source.
    \item[Verifier] Reopens the saved table and checks the requirements already encoded.
  \end{description}

  \vfill
  Record the green result before asking for help. A later change should preserve
  that baseline while adding evidence for our specific goal.
\end{frame}

\begin{frame}{Step 2: locate the missing evidence}
  The current verifier establishes that mortality values are observed and
  nonnegative. It does not yet connect the column to its documented identity
  and unit.

  \vspace{0.5em}
  \begin{description}
    \item[Table plan] Under-five mortality per 1,000 live births.
    \item[Dictionary] \texttt{under5\_mortality}; \texttt{SH.DYN.MORT}; deaths
      before age five per 1,000 live births.
    \item[Missing check] Does the verifier confirm that the expected dictionary
      entry is present before accepting the saved table?
  \end{description}

  \vfill
  We choose the gap. The agent does not choose the policy question, unit, or
  meaning of the variable for us.
\end{frame}

\begin{frame}[fragile]{Step 3: ask for one reviewable proposal}
\begin{lstlisting}
Goal: Propose the smallest change to code/02-verify-analysis.R
that confirms the under5_mortality dictionary entry has indicator
code SH.DYN.MORT and a unit stated per 1,000 live births.
Context: Read the verifier and data/documentation/
indicator-dictionary.csv.
Permission: Read only. Show a proposed diff; do not edit yet.
Constraints: Do not change the table, sample, key, or variables.
Done when: Explain what the new check proves and name the command
we should rerun after reviewing it.
\end{lstlisting}
\end{frame}

\begin{frame}{Step 4: inspect before allowing an edit}
  Read the proposal together. Ask:
  \begin{enumerate}
    \item Does it read the checked-in dictionary rather than invent a definition?
    \item Does it test both the indicator code and the documented unit?
    \item Does it leave the table, population, key, and transformation unchanged?
    \item Can we predict what will pass or fail before running it?
  \end{enumerate}

  \vfill
  Only after this review do we either reject the proposal, request a revision,
  or permit the smallest acceptable edit.
\end{frame}

\begin{frame}{Checkpoint 3: which proposal serves the goal?}
  Compare two possible checks:

  \begin{description}
    \item[Proposal A] Require every mortality value to be at most 100 because
      the variable sounds like a percentage.
    \item[Proposal B] Confirm that the dictionary entry is
      \texttt{SH.DYN.MORT} and states a unit per 1,000 live births.
  \end{description}

  \vspace{0.5em}
  Decide together:
  \begin{enumerate}
    \item Which proposal answers the goal we set?
    \item Why is the other proposal unsupported?
    \item What result should the revised verifier display?
  \end{enumerate}

  \vfill
  \centering
  \textbf{2 minutes discuss}\qquad$\longrightarrow$\qquad
  \textbf{2 minutes share}
\end{frame}

\begin{frame}[fragile]{Step 5: apply one change and rerun the evidence}
  If the proposal survives review, allow the edit and rerun only the independent
  verifier:

\begin{lstlisting}
Rscript code/02-verify-analysis.R
\end{lstlisting}

  We are finished only when:
  \begin{itemize}
    \item the new dictionary check is visible and passes;
    \item all earlier checks still pass;
    \item the table itself has not changed;
    \item we can explain what the added check proves---and what it does not.
  \end{itemize}

  \vfill
  The agent proposes code. The class decides whether the evidence is adequate.
\end{frame}

\begin{frame}{Decisions the analyst keeps}
  \begin{itemize}
    \item The meaning of one row.
    \item The population represented by a filter.
    \item Whether a transformation fits the policy question.
    \item Whether current metadata can be interpreted historically.
    \item Whether missing coverage weakens the comparison.
  \end{itemize}

  \vfill
  The analyst interprets the evidence that the agent exposes.
\end{frame}

\begin{frame}{Updating public data is an extension}
  Extending one indicator beyond 2022 can be useful. It also adds:
  \begin{itemize}
    \item an internet and API dependency;
    \item retrieval dates and version changes;
    \item possible revisions to earlier years;
    \item new metadata questions.
  \end{itemize}

  \vfill
  First build the frozen table correctly. Then extend it with a separate record.
\end{frame}

\begin{frame}{What we learned in Lesson 2}
  \begin{itemize}
    \item Define the table we need before using data verbs.
    \item Every verb should have a reason and a check.
    \item A join must preserve the intended key and unit.
    \item The analysis table should rebuild from a protected source.
    \item The agent improves one bounded part under analyst review.
    \item A separate verifier must inspect the saved object and report evidence.
  \end{itemize}
\end{frame}
