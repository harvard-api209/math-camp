WHY THIS LAB

Build one table that you can explain.

A useful analysis begins with a table whose unit, variables, sample, and transformations are understood. The goal is one checked object with a pipeline that you can explain.

Everyone begins with the health example and a supplied scaffold. You may adapt another policy track only after the common table passes. Work together to diagnose problems. Keep your own script and be able to explain it. The lab has no submission or grade.

DONE WHEN

Your script rebuilds the table from the frozen file, the country-year key is unique, the build record reports the expected structure, and you can explain one important decision without the agent.

library(tidyverse)

wdi <- read_csv(
  "data/derived/math-camp-wdi-2000-2022.csv",
  show_col_types = FALSE
)

health <- wdi |>
  select(
    iso3c, country, year, income_level_current,
    gdp_per_capita_ppp, under5_mortality
  ) |>
  filter(year >= 2000) |>
  mutate(log_income = log(gdp_per_capita_ppp))

stopifnot(!anyDuplicated(health[c("iso3c", "year")]))

Run one verb at a time. Before each run, mark whether rows, columns, values, ordering, or the unit should change. After the run, produce evidence that the expected change occurred.

Checkpoint Question Visible check
After select() Did the key survive? names() and glimpse()
After filter() Who left the sample? Rows, countries, and year range before/after
After mutate() Is the new variable defined for valid inputs? Missingness, range, and one hand check
After a join Did rows multiply or fail to match? Key test, row count, and anti_join()

45–52 MINUTES

Delegate one bounded improvement.

BOUNDED AGENT PASS 
Goal: Review my health-table pipeline and propose checks for its stated contract.
Context: Read my script and the indicator dictionary. The unit must remain country-year.
Permission: Read and propose a patch; do not run it or alter frozen data.
Constraints: Keep object and column names in lowercase. Do not redesign the pipeline or make a policy claim.
Proof: Explain which contract field each check tests and show the smallest proposed diff.

Inspect the diff. Keep only checks you can explain. If the agent proposes a different population, transformation, or key, treat that as a substantive change requiring your decision.

52–60 MINUTES

Keep a short build record.

  • □Input and output row counts are recorded.
  • □iso3c + year is unique.
  • □The year range matches the contract.
  • □Missingness and plausible ranges are visible for both indicators.
  • □Any unmatched join keys are listed.
  • □The script starts from a saved file and runs without objects left in the console.

Finish with four sentences: what one row represents; which observations were excluded; what the logged variable means; and which limitation remains for the policy question.
